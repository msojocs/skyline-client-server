# Skyline 启动卡点分析（2026-09-13）

> 分析对象：本仓库 `skyline/electron` 分支启动的微信开发者工具 Electron（项目 `awesome-skyline/examples/address-book`）。
> 约束：全程只读，未修改任何代码；通过 CDP/Node Inspector 实测运行时状态。

## 结论（TL;DR）

启动流程卡在 **Skyline 引擎窗口创建（createWindow）** 这一步，且是**永久性失败**而非慢：

- IDE 项目窗口 renderer 在 `createSkylineEngine()` 中 `await skylineController.createWindow(t)` 永远挂起，
  等待 appservice 回 `SAC6 (SKYLINE_CREATE_WINDOW_RESPONSE)` 打开 windowBarrier；
- appservice（逻辑层 webview，实际运行在 skyline-client-server 的 Electron 里）收到
  `SAC0 (SKYLINE_CREATE_WINDOW)` 后执行 `createWindow`，第一步
  `safeSkylineRequire("sharedMemory/sharedMemory.node")` 即抛出
  **`无效的 ELF 头`**（实测复现），异常导致 SAC6 永远不会回；
- 根因：skyline-client-server 的 `packages/electron` 当前以**原生 Linux Electron** 运行，
  但其 `node_modules` 里的 `sharedMemory/sharedMemory.node` 和 `skyline-addon/build/skyline.node`
  都是 **Windows PE32+ DLL**（为 Wine 部署准备的），Linux 原生进程无法加载。
- 后果链：createWindow 抛错 → SAC6 不回 → IDE barrier 不开 →
  `SkylineRenderer.startRender()` 从未执行（pageframe 无 canvas、全黑）→
  路由 appLaunch 无法完成 → 逻辑层 `getCurrentPages()` 为空 → 无共享内存文件、无首帧。

## 根因

```
$ file packages/electron/node_modules/sharedMemory/sharedMemory.node
PE32+ executable for MS Windows 5.02 (DLL), x86-64   (2,896,072 字节, 9月10日 22:45)
$ file packages/electron/node_modules/skyline-addon/build/skyline.node
PE32+ executable for MS Windows 5.02 (DLL), x86-64
```

而当前 skyline-electron 是 **Linux 原生 Electron 36.6.0**（`ps` 可见
`skyline-client-server/node_modules/.pnpm/electron@36.6.0/.../electron packages/electron`，
非 Wine）。在逻辑层 webview 内实测（CDP evaluate）：

```js
window.__global.safeSkylineRequire('sharedMemory/sharedMemory.node')
// → Error: .../sharedMemory.node: 无效的 ELF 头
window.__global.safeSkylineRequire('skyline-addon/build/skyline.node')
// → Error: .../skyline.node: 无效的 ELF 头
```

即：这套 `node_modules` 是为 **Wine/Windows Electron** 部署准备的 PE 二进制
（与项目既有结论一致：官方 SkylineShell 引擎只有 Windows 版），
用原生 Linux Electron 跑 `packages/electron` 必然在 createWindow 的第一个 require 处失败。

## 附：分析方法与复现命令

1. `curl http://127.0.0.1:9222/json/list` / `:9229/json/list` 枚举调试目标
   （9222=skyline-electron CDP，9229=微信主进程 Inspector）。
2. 主进程侧（9229，`process.mainModule.require('electron')`）：
   - `BrowserWindow.getAllWindows()` → 窗口/URL/loading 状态；
   - `webContents.capturePage()` → 截图（win1.png / pageframe.png）；
   - `webContents.executeJavaScript(...)` → 读 pageframe 内 `SkylineRenderer.instance`、
     canvas 数量、`__wxConfig`、`__global` 键。
3. CDP 侧（9222，逻辑层 webview 目标）：
   - `getApp()` / `getCurrentPages()` / `__wxConfig` → 逻辑层状态；
   - `__global.skylineManager.skylineWindows.size` → 引擎窗口数；
   - `safeSkylineRequire` 试加载 → 复现 "无效的 ELF 头"（只读 require，无副作用）。
4. `ss -tnp` 核对 3001/3002 连接已建立（排除"客户端根本没连上 server"）。
5. `ls /dev/shm` 无 `skyline_*.dat`（排除"createWindow 已执行但后续卡住"——
   `setMemory` 若执行过必然落文件）。
6. `file` 确认两个 .node 均为 PE32+。
7. WeappLog（`~/.config/wechat-devtools/…/WeappLog/logs/2026-09-13-20-51-*.log`）确认编译完成。

## 修复方向（不在本次范围内，仅记录）

让 appservice 跑在能加载 PE 二进制的环境里：按既定架构用 **Wine + Windows Electron**
启动 `packages/electron`（其 node_modules 正是为此准备的），而不是 Linux 原生 Electron；
或提供 Linux ELF 版 sharedMemory + 可用的 Linux 引擎（引擎官方无 Linux 版，故实际是前者）。
